# AGENTS.md

Two independent apps in one repo. There is no root build, workspace, or task runner file — always `cd` into `backend/` or `Frontend/` before running anything.

- `backend/` — Spring Boot 4.1.1 REST API (Java 25) built with the Maven wrapper; base package `com.example.backend`. JWT auth via Spring Security.
- `Frontend/` — React 19 + TypeScript + Vite (npm). Stack: React Router 7, Zustand, TanStack Query, Tailwind CSS 4, Axios. The marketing landing at `/` is built; domain features have not started.
- Branches: `develop` (current) and `main`; remote `origin` = `Shoutt4/Nottia`.

## Commands

Backend (from `backend/`; use `mvnw.cmd` / `.\mvnw` in PowerShell):

- Run: `./mvnw spring-boot:run`
- Test all: `./mvnw test`
- Single test: `./mvnw -Dtest=BackendApplicationTests test`
- Package: `./mvnw clean package`

Frontend (from `Frontend/`):

- Install: `npm install`
- Dev server: `npm run dev`
- Build: `npm run build` (runs `tsc -b` then Vite)
- Lint: `npm run lint` (ESLint flat config)

There is no frontend test runner; `tsc -b` is the only type check and it runs only as part of `npm run build`.

## Frontend structure

Organized by concern. Domain features live in `features/<name>/` and are imported through their barrel (`@/features/<name>`).

### Code conventions

- **No `any`, no `unknown`**: ESLint rejects both (`@typescript-eslint/no-explicit-any` + `no-restricted-syntax` on `TSAnyKeyword`/`TSUnknownKeyword`). When the API is involved, copy the backend DTO into an interface and type the Axios call (`http.get<NotaResponse>(…)`); do not parse a generic body by hand. `getAppError`/`getErrorMessage` take `Error | null`, so narrow a `catch` value with `error instanceof Error` before passing it.
- **300 lines per file max**: enforced by ESLint (`max-lines`, 300 sin contar comentarios ni líneas en blanco). Split before a file grows past it. The note editor is `pages/NoteEditorPage.tsx` (load only) + `components/NoteEditor.tsx` (shell) + `NoteEditorList`/`Header`/`Body`/`Footer` + `hooks/useNoteEditor.ts`; the icons are `components/ui/icons/<group>.tsx`.

- `main.tsx` mounts `AppProviders` (theme + TanStack Query) around `App`.
- `app/` — app wiring: `App.tsx` renders `RouterProvider`; `AppProviders.tsx`; `ThemeProvider.tsx` (toggles `.dark` on `<html>` from the store); `router.tsx` (route table); `queryClient.ts`. Route guards live here: `ProtectedRoute.tsx` (private routes → `/login` when logged out), `PublicOnlyRoute.tsx` (landing/login/register → `/dashboard`, or `/admin/usuarios` for ADMIN, when logged in), both driven by `useIsAuthenticated.ts`, plus `AdminRoute.tsx` (the `/admin` panel requires the JWT `role` to be `ADMIN`). Private pages nest inside `ProtectedRoute` → `SidebarLayout` (the sidebar shell). `SidebarLayout`'s `<main>` is **full width** (no `max-w`): each page centers its own content (`mx-auto w-full max-w-5xl px-5 sm:px-8`), so the Home cover can go full-bleed; for the note editor route it drops the `py-8` and takes the viewport height (`h-[calc(100dvh-3.5rem)] lg:h-dvh`) so the editor scrolls internally. When adding a page, update `router.tsx` **and** `config/routes.ts` together and nest it under the right guard (or leave it top-level for the 404).
- `pages/` — top-level pages, **not** under `features/`. `pages/landing/` is the marketing landing at `/`: `LandingPage.tsx` composes `Navbar`, `Hero`, `Features`, `Showcase`, `CallToAction`, `Footer`, with the feature-card list in `data.ts`. `pages/ComingSoonPage.tsx` is the catch-all 404 placeholder.
- `features/` — `auth/` (`api/authApi.ts`: `POST /api/auth/login`, `POST /api/auth/register`, `GET /api/email/verify-email`; `pages/LoginPage.tsx`, `RegisterPage.tsx`, `VerifyEmailPage.tsx`; `components/AuthLayout.tsx` shared by login/registro, `LoginForm.tsx` / `RegisterForm.tsx`, `FormField.tsx`; `hooks/useLoginForm.ts`, `useRegisterForm.ts`, `useVerifyEmail.ts`, `useShake.ts`). Login stores the JWT (`setToken`) and redirects to `/dashboard` (or `/admin/usuarios` when the JWT role is `ADMIN`); an unverified account (backend 404) shows "Verifica tu correo antes de iniciar sesión". Register posts `{ nombre, apellido, email, password }`, checks the repeated password client-side and swaps the card for "Revisa tu correo" (the account is inactive until the emailed link is opened; the token lasts 15 min); a duplicate email (409) is shown on the email field. `/verify-email` is public and sits **outside** both guards; `useVerifyEmail` is a TanStack Query one-shot so StrictMode doesn't fire the single-use token twice. Login reports results with `toast.success` / `toast.error` (generic message, no account enumeration). `dashboard/` is the **visual** Home (Inicio, `/dashboard`): `pages/HomePage.tsx` (full-bleed cover + title + notes rail) with `components/CoverBanner.tsx` + `CoverSurface.tsx` (full-width cover whose height is in `dvh`, so it adapts to the window and zoom) and `components/BoardSettingsDialog.tsx` (the "Editar tablero" pencil: upload an image, pick a gradient preset, change the cover height, reset; all persisted in `nottia-cover`). `lib/cover.ts` holds the presets + height classes and `lib/image.ts` downscales uploads to a JPEG data URL. `notes/` is the notes domain wired to the real API: `api/notesApi.ts` (`POST /api/notas/save`, `PUT /api/notas/update/{id}`, `GET /api/notas/{id}`, `GET /api/notas/all?page=&size=`) typed with the backend DTOs from `types/` (`NotaResponse`, `PageResponse<T>`, `SaveNotaResponse`); `hooks/useNotes.ts` (`useNotes` page query for the editor list, `useInfiniteNotes` for the Home carousel, `useNote` detail using the list as `initialData`, `notesKeys`, `NOTES_PAGE_SIZE`/`NOTES_RAIL_PAGE_SIZE`) and `hooks/useNoteMutations.ts` (`useCreateNote`, `useUpdateNote` patching every cached list); `types/`, `lib/format.ts`, `lib/prompts.ts`, `components/` (`NoteCard`, `NotesRail` = arrows + "load next page" when scrolled to the end, `AddNoteCard`, `NoteListItem`, `NoteCardSkeleton`). Creation sends `idUsuario` from the JWT (`getCurrentUser().id`) and reuses the last known `idCuaderno` until a notebooks API exists. `pages/NoteEditorPage.tsx` is the full-screen editor at `/notas/:noteId` (`ROUTES.notes` + `notePath(id)`): own notes list, breadcrumb, **manual** save ("Guardar cambios" or Ctrl/⌘+S; no autosave) with a "Cambios sin guardar" / "Guardando…" / "Todos los cambios guardados" footer, and an expand/minimize button (`hooks/useFullscreen.ts`, Fullscreen API on the editor canvas). The editor lives **inside** `SidebarLayout` (the app menu stays visible) and fills the viewport height; `<<` only collapses the notes list (grouped by day), while fullscreen hides the menu and the list too. The page only loads the note; `components/NoteEditor.tsx` composes `NoteEditorList`/`Header`/`Body`/`Footer`, with local state and manual save in `hooks/useNoteEditor.ts`. "Compartir" is a custom dropdown (copiar enlace / copiar la nota como texto — `lib/share.ts`, no native share sheet, no backend). `profile/` is the account page (`/perfil`, "Información de la cuenta"): `api/profileApi.ts` (`GET /api/usuarios/me`), `hooks/useProfile.ts` (TanStack Query; the sidebar, the welcome page and the page share its cache), `components/` (`AccountNav`, `PlanCard`, `ProfileField`, `ProfileSkeleton`), `lib/format.ts` (`fullName`, `formatDate`), `types/` (`UserProfile`). Display data no longer comes from the JWT. `admin/` is the ADMIN panel (`/admin` → `/admin/usuarios`, `/admin/perfil`): `pages/AdminUsersPage.tsx` lists `GET /api/usuarios/all` paginated (10 per page) with `api/adminUsersApi.ts` + `hooks/useAdminUsers.ts`; `/admin/perfil` renders `ProfilePage` with its `admin` variant; `AdminRoute` guards by the JWT `role`, and `SidebarLayout` swaps to `adminNavItems` under `/admin`. `sidebar/` is the private app shell: `components/` (`SidebarLayout.tsx` = sidebar + mobile top bar + `<Outlet />`, `Sidebar.tsx` = collapsible rail on `lg` / drawer on mobile, `SidebarNavItem.tsx`, `SidebarUser.tsx`, `SidebarThemeToggle.tsx` = theme switch inside the sidebar), `hooks/useSidebar.ts` (collapsed state from the store), `lib/navItems.ts` (nav config), `types/` (`NavItem`). New nav entries go in `lib/navItems.ts`.
- `stores/` — Zustand. `uiStore.ts` persists `{ theme, sidebarCollapsed }` as `nottia-ui`, the exact key/shape the `index.html` inline script reads before React mounts (it reads `state.theme`; don't rename it or the theme will flash). Access it as `useUiStore((s) => s.theme)` / `s.toggleSidebar()`. `toastStore.ts` holds the toast queue (not persisted). `coverStore.ts` persists the Home cover and its height under `nottia-cover`.
- `components/brand/` — `Logo` (mark identical to `public/favicon.svg`) and `LogoWordmark`; use them everywhere the brand appears. `components/ui/` — `icons/` (inline SVG icons, no icon library: `base.tsx` + `actions.tsx` + `navigation.tsx` + `ui.tsx`, re-exported from `index.ts`; add new ones in the matching file), `Button.tsx` + `buttonStyles.ts` (`buttonClass` for `<Link>`s), `ThemeToggle.tsx`, `Reveal.tsx` (scroll-in animation via IntersectionObserver), `Avatar.tsx` (photo via `urlAvatar` with initials fallback). Global toasts: `Toaster.tsx` + `Toast.tsx` are mounted once in `AppProviders` and fired with `toast` from `@/lib/toast`.
- `lib/` — `utils.ts` (`cn` = clsx + tailwind-merge, `getInitials` for avatars), `errors.ts` (`getAppError` normalizes any Axios/network/exception error into a standard `AppError` — `kind`, `status`, `fields`, UI-ready Spanish `message`; **always** use it before showing an error), `toast.ts` (`toast.success/error/warning/info/dismiss/clear`).
- `config/` — API access layer. Import via the barrel: `import { http } from '@/config'`. `http.ts` is the single shared Axios instance (baseURL from `API_URL`, 15s timeout, attaches `Bearer <token>` when present, clears the token and emits `nottia:unauthorized` on a 401); `env.ts` exports `API_URL`; `token.ts` stores the JWT under `nottia-token` (localStorage when "Recordarme" is on, sessionStorage otherwise) and exposes `getToken`/`setToken`/`clearToken`/`isAuthenticated` (checks the `exp` claim) and `getCurrentUser()` (decodes `sub`/`email`, `id_usuario`, `nombre`, `role`, `urlAvatar`, `phone` for the sidebar/profile/welcome). Do not create ad-hoc `axios` instances elsewhere.
- `styles/index.css` — Tailwind v4 entry. Its `@theme` block defines the "Lavanda" tokens (`canvas`, `surface`, `line`, `ink`, `muted`, `accent`, `accent-hover`, `accent-soft`, `on-accent`, `danger`, `danger-soft`, `on-danger`, plus landing accents `accent-2`/`accent-3`). Use the semantic utilities (`bg-surface`, `text-muted`, `border-line`, …) instead of raw Tailwind color scales. Dark mode uses `@custom-variant dark (&:where(.dark, .dark *))` and only redefines those tokens — don't add per-component `dark:` styles or hardcode a light/dark pair. Also defines `.aurora` (background wash), `--animate-float`/`--animate-rise`/`--animate-toast-in`/`--animate-toast-out`, and `.reveal`/`.is-visible`.
- Animations are CSS-only (tokens + `Reveal`); no animation library is installed. Keep it that way unless a concrete need appears.
- `@/` alias → `src/`, configured in both `vite.config.ts` and `tsconfig.app.json`.
- Brand/preview assets: `public/favicon.svg`, `public/icons.svg` (SVG sprite of social icons, referenced by `id`), and the static mockups `design/palette-preview.html` / `design/logo-preview.html`.

Dev API wiring: `.env` sets `VITE_API_URL=http://localhost:8080/`, which `config/http.ts` uses as the Axios baseURL, so the app calls the backend cross-origin (allowed by the backend CORS allowlist). Request paths therefore start with `/api/...`. Setting `VITE_API_URL=/api` routes through the `vite.config.ts` proxy instead.

## Backend notes

- Requires JDK 25 (`java.version` in `pom.xml`); the Maven wrapper pins Maven 3.10.0.
- `src/main/resources/application.properties` points at a shared remote **Neon PostgreSQL** instance with committed credentials and runs Hibernate with `ddl-auto=update` against schema `Spring` (`show-sql=true`). Startup and the `@SpringBootTest` need network access to Neon and fail offline. Changing entities mutates the shared schema — treat entity edits with care.
- JWT: `jwt.secret=${JWT_SECRET:...}` and `jwt.expiration=86400000` (24h); override the secret with the `JWT_SECRET` env var.
- Security (`config/SecurityConfig.java`): stateless, CSRF disabled, only `/api/auth/**` is public — everything else requires authentication, and a missing/invalid token returns **401** via a custom entry point (not Spring's default 403). `@EnableMethodSecurity` is enabled.
- CORS (`config/CorsConfig.java`): allowlist `http://localhost:5173` and `http://localhost:3000`, credentials allowed. Its method list contains a typo — `"PATH"` instead of `"PATCH"`.
- Auth flow: `service/auth/AuthService.java`, `controller/auth/AuthController.java`. `POST /api/auth/register` (201) and `POST /api/auth/login`, both returning `{ "token": ... }`. User entity `entity/auth/Usuario.java` (table `usuario_ann`); roles are the `Role` enum (`USUARIO`, `ADMIN`) and registration always assigns `USUARIO`.
- `PUT /api/usuarios/Update` (`controller/usuario/UsuarioController.java`) updates the caller. It is `@PreAuthorize("hasRole('USUARIO')")` and takes the raw `Authorization` header (client must send `Bearer <token>`), re-reading `id_usuario` from the token.
- Error shape: `GlobalExceptionHandler` maps `authExceotion` to `{message, status, succes}` and bean-validation failures to `{message, error:{field: message}}` (400).

## Gotchas

- Preserve existing class and file names even when misspelled — they are referenced across the codebase: `LoginRequetDTO`, `authExceotion`, `createUsuario`, `convertirUsuarioRequest`. Renaming breaks compilation.
- `Usuario.apellido` is `unique = true` while `email` is not, even though dedup uses `existsByEmail`. Expect DB constraint errors on duplicate surnames.
- `AuthRequestDTO` and `UsuarioRequestDto` carry JPA `@Column`/entity annotations although they are not entities — those have no effect; only the `jakarta.validation` constraints are enforced.
- Windows/case gotcha (frontend): `tsc -b` fails if two files in `src/` differ only in casing (e.g. `features.ts` next to `Features.tsx`) because the `include: ["src"]` scan is case-insensitive. Give sibling files distinct names.
